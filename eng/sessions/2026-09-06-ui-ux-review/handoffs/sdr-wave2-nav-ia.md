### Verdict
- **Direction:** `mixed`
- **Why:** Wave 2 is trying to make the chrome the product map — four jobs, a quiet Lab, visible current page, skip-to-content, a ticker way out of a detail, Lab pages that are not traps — without a SPA, a tenth URL, or a second fair value. Designed today, that is one chrome module: `base.html` as the only site map, a single page-render helper that injects a small `nav` value, two instances of the existing `.disclose` widget (each pair scoped so the sibling combinator stays one-to-one), and crumbs that occupy the back-link slot already on run/analyze/compare detail. The session as written is that map in the right files, then a patch around the old tree: “pass `request` (or `nav`) into every `_render`” leaves five cloned helpers and a dozen `get_template().render` bypasses; `crumbs-empty` reaches into blotter- and jobs-owned files; a second Lab checkbox dropped into the same `.header-nav` will light both panels under the existing `~` rule. Goal and split of work are right; the chrome interface is not yet the from-scratch one.
- **Do:** `reshape`

### Keep
- FastAPI + Jinja, shareable GET queries, all nine URLs, identity strings, no `/ticker/META` hub, no mega-menu, no second FV. Winner A from the parent Design-it-twice (compose in this tree, not a sidebar/SPA) is still the right product shape.
- Primary vs Lab as the only header grouping; Lab is demotion, not a new product. Phone reuses `.disclose` rather than a new menu primitive. Wave 5 still owns disclose tab-order, `:focus-visible`, and 800→1100.
- Skip link as the first focusable, `id="content"` on `<main>`, `aria-current="page"` plus one CSS weight — server-rendered, not a `runs.js` highlighter. Brand is a home link; nav word Compare; operator tagline instead of data-plane jargon.

### Candidates

### 1. One page render injects `nav`
- **Change:** Collapse the five identical `_render` helpers (`pages`, `analyze`, `compares`, `architecture`, `harness`) into one `render_page` on the Jinja environment (home: `templating.py`). It always injects a small `nav` (`current` ∈ a closed set: runs / analyze / compare / portfolio / harness / architecture / experiments / calibration / health) derived from a prefix table in that one function. Fragments stay a separate render with no chrome. Full pages that extend `base.html` and today bypass `_render` (`page_runs`, `error.html` from `_error` / `app.py` / `artifacts.py`, `report.html`, `artifact.html`) go through `render_page` or they will silently lack current-page. `base.html` matches `nav.current == 'analyze'`, not `request.url.path`. Phone closed Menu label (`Menu · Analyze`) is server text from the same value. Do not put FastAPI `Request` in the template; do not compute current-page in `runs.js`.
- **Why:** Change amplification and unknown unknowns: “every `_render`” is not every chrome page, and the list of bypasses is not in the brief. Information leakage if each template repeats path prefixes (`/analyze` vs `/analyze-artifact` vs `/runs` vs `/`). Overexposure of `Request`. The from-scratch interface is “render an HTML page” with chrome implied; the plan is “remember to pass a bag into each clone.” This is the increment that is an abstraction. No deadline or compatibility constraint blocks it — Wave 2 already has the write allowlist on `apps/analysis_web/`.
- **When:** `this change`

### 2. Wrap each disclose pair
- **Change:** Markup is two groups, not nine peers in one list: primary `<nav aria-label="Primary">` (Runs · Analyze · Compare · Portfolio) and Lab `<nav aria-label="Lab">` (the five utilities). On phone, each group is its own `.disclose` instance (Menu / Lab) — checkbox + label + panel wrapped in a box so `.disclose:checked ~ .disclose-panel` cannot see the other panel. Do not add a second `.header-nav .disclose:checked ~ .disclose-panel` special case; that selector already matches every following panel and is what `PhoneChromeTests` asserts today. Header CSS only quiets Lab links. Keep `id="nav-runs"`. Put the grouping rule in a short `base.html` comment next to the markup (two instances of disclose, not a new widget). Wave 5 still hides `.disclose` on desktop and paints the focus ring.
- **Why:** Special–general mixture and a real unknown unknown: one checkbox-panel pair per container is the disclose contract (“Callers own layout”). Two checkboxes as siblings in `.header-nav` make Menu-open also open Lab. Tests that still find the old selector will pass while the phone chrome is wrong. Visual F2’s “still one `<nav>`” loses to two labeled navs — simpler for the common case (SR hears two maps; desktop is still one header row).
- **When:** `this change`
