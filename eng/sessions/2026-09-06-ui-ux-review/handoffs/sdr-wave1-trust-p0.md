# Strategic design review — Wave 1 ui-trust-p0

Grain: feature / implementation plan (module boundaries and shape of the change). Not an implementation.

### Verdict
- **Direction:** `mixed`
- **Why:** Wave 1 is trying to make the operator believe the product: a compare grid that shows the packet’s numbers, unknown HTML routes that stay in chrome, a completed Analyze that is not painted as a failure, and a Compare ticker abort that is not also an empty list. Designed today, those are four surfaces in the existing FastAPI+Jinja tree — a headline *view* (English labels and formatted cells; `headline.json` stays a compare_jobs packet), a content-negotiated HTML 404 with a default exit on `error.html`, Analyze notes keyed off job status, and Compare abort XOR empty (same contract as Runs). The session split, file ownership, and the last two slices are that structure. The first two as written are still patches: the template keeps talking to a dict key named `values`, and the 404 handler is specified as “add HTML for Accept: text/html” without an error model for JSON `/api` 404s.
- **Do:** `reshape`

### Keep
- Compose in the current tree (plan Design-it-twice winner A): FastAPI + Jinja, shareable GET, no SPA, no second fair value / blended MoS. Catalog remains the only FV source; compare headline stays helper snapshots, not a target.
- Wave 1 as the trust increment, before nav regroup (Wave 2) and the blotter (Wave 3). File ownership is a real boundary: this session writes `compare_detail.html`, `error.html`, `analyze_detail.html` (class only), `compares.html` (abort branch), and an `app.py` 404 handler — not `base.html` or `runs_table.html`.
- Analyze `.err` only for `failed` / `cancelled` / abandoned; reconcile strings stay visible as `.muted`. That redefines the slot from “any `job.error` is a failure” to “status decides severity.” Do not parse the `abandon.json present on finalized session…` string, and do not reshape `packages/research_jobs` / `job.json` in this wave (`archive/research_jobs` is append-only; existing complete jobs already store that warning on `error`).
- Compare unknown ticker keeps HTTP 404 + `form.is-abort` + the abort alert. Only the empty-packet sentence is gated off. Same abort-vs-empty idea as Runs (`error_kind == 'ticker_not_found'` vs “No runs”); do not invent a shared `error_kind` module just to change one `{% else %}`.
- Default `← Runs` on `error.html` (optional `back_href` unused → `/`). That pulls the missing exit into the one template every existing `_error()` already renders. Do **not** migrate the six router `_error` copies (pages, analyze, compares, artifacts, architecture, harness) in this wave — that is change amplification into files later waves own. Busy / Grok-missing staying on `error.html` until Wave 4 (form re-render) is the right deferral.
- Verify against a real packet render and `Accept: text/html`, not a source grep for `row['values']`. Existing `test_api_start_and_detail` and `test_compares_unknown_ticker_aborts` are the homes.

### Candidates

### 1. Headline view, not packet-in-template
- **Change:** In the compare detail path (a helper next to `fmt_num` in `apps/analysis_web/templating.py`, or a few lines in `page_compare_detail`), project `headline.json` into a display table: `{sessions, rows: [{label, cells: [str, …]}]}`. Labels live in that one map (`As-of`, `FV base`, `FV bear`, `FV bull`, `MoS %`, plus English for `audit_verdict` / sector / region / `verdict_line`). Cells go through `fmt_num` (None → `—`; non-numerics stay strings). The template iterates `row.label` / `row.cells` only. Do not rename the on-disk `"values"` key (existing packets + `packages/compare_jobs/headline.py` + pins). Do not add a blended delta column.
- **Why:** `{{ row.values[key] }}` is information leakage: a compare_jobs packet key that collides with `dict.values` leaked into Jinja, so the grid is blank while the file is full — an unknown unknown the next `row.items` / `row.keys` repeats. Bracket notation in the template is a tactical patch that leaves the collision in the interface. From-scratch, the template never sees the packet shape; Python owns formatting and labels (principle: pull complexity downwards; simple interface for the common case). A 9-way `{% if row.field == 'fv_base' %}` in the template is the same leak in another costume.
- **When:** `this change`

### 2. 404 is content negotiation, not “make it HTML”
- **Change:** Register a handler for unmatched / `HTTPException` 404 in `app.py` whose *interface* is: if the request wants HTML (`Accept` prefers `text/html`), render `error.html` with message, status 404, and the default back link; otherwise keep JSON `{"detail": …}` (FastAPI’s current API contract). Pass `request` into that render even if unused (Wave 2’s `aria-current` will need it; today’s 500 handler and `_error()` omit it). Do not pass `detail=` traceback on 404. Do not replace the `Exception` → HTML 500 handler. Do not HTML-ify `/api/*` 404s that send `Accept: application/json` (job pollers already set that). Pytest: unknown path + `Accept: text/html` is chrome + `← Runs`; an `/api/…` miss with JSON Accept stays JSON.
- **Why:** The JSON 404 is Starlette’s default `HTTPException`, not a missing template. A handler that always returns HTML (or that treats any `Exception` subclass as HTML) either leaves `/api` as an unknown unknown or turns fetch 404s into an HTML body that `r.json()` cannot parse — change amplification into every API test and `analyze_detail.js` / `compare_detail.js`. Content negotiation is the from-scratch error model for a dual HTML+JSON app; “HTML 404 handler for Accept: text/html” as a one-liner in the brief is that idea unnamed, so an implementer can still patch the 500 handler’s render block and swallow JSON. Unifying router `_error()` helpers is not this increment.
- **When:** `this change`
